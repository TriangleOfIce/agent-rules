# Переносимые настройки агента

Общие правила, воркфлоу и шаблоны для воспроизведения рабочего окружения на другом устройстве. Репозиторий не содержит код продуктовых проектов, их локальные карты, текущие задачи или учётные данные.

## Что входит

- `AGENTS.md` — основной автономный набор правил для агента.
- `CLAUDE.md` — архивное подключение тех же правил в Claude Code; сохранено для справки и не обновляется.
- `docs/` — маршрут задачи, проверка, ревью, Git, документация, память, субагенты и KMP.
- `templates/` — шаблоны локальных правил, памяти, рабочих документов и ADR.
- `kimi-code/` — не секретные настройки Kimi Code и пула вторичных моделей.
- `claude/` — **архивный снимок** строгого личного профиля Claude Code, Kotlin-правил и защитных hooks. Сохранён только для справки: больше не используется и не обновляется.
- `bootstrap.sh` — безопасное подключение общих правил к рабочему каталогу без перезаписи существующих файлов.

## Быстрое подключение

```bash
git clone git@github.com:TriangleOfIce/agents.git
./agents/bootstrap.sh /path/to/Work
```

Скрипт создаёт символические ссылки `AGENTS.md`, `CLAUDE.md` и `agent-conventions`, а также начальные `memory/projects.md` и `backlog/README.md`, если их ещё нет. Существующие файлы не перезаписываются: при конфликте скрипт останавливается, чтобы правила можно было объединить вручную.

Подробная настройка и проверка: [docs/setup.md](docs/setup.md).

## Основные принципы

1. Сначала локальные инструкции проекта, ожидаемый результат и критерий проверки.
2. Минимальное самодостаточное изменение без побочного рефакторинга.
3. Решения пользователя не пересматриваются; неоднозначность с разными последствиями уточняется.
4. Факты проверяются по коду и первоисточникам; наблюдение сначала диагностируется.
5. Проверяется реальный сценарий, затем финальный diff/status; непроверенное явно называется.
6. Публикация, запись во внешние системы и необратимые действия выполняются только по явному запросу.
7. Постоянная память отделена от временных документов задачи и локального бэклога.
8. Субагенты получают узкие независимые подзадачи; основной агент отвечает за решение и проверку.

## Что сознательно исключено

- Исходный код и настройки конкретных продуктов.
- Названия и пути локальных репозиториев, карта проектов и продуктовые исключения.
- Журналы, исследования и планы текущих задач.
- Токены, OAuth-идентификаторы, ключи SSH, cookies, история сессий и локальные credentials.
- Абсолютные пользовательские пути, доверенные каталоги и исключения конкретного устройства.
- IDE-настройки, кэши, логи и автоматически созданные файлы.

KMP-документ содержит только переносимые инженерные правила, не сведения о текущих проектах.

## Источники практик

- [Kimi Code: Configuration files](https://moonshotai.github.io/kimi-code/en/configuration/config-files.html) — схема `config.toml`, пул secondary-моделей и приоритет effort.
- [Google Engineering Practices: Code Review](https://google.github.io/eng-practices/review/) — небольшие изменения, содержание ревью и комментарии.
- [Diátaxis](https://diataxis.fr/) — назначение tutorial, how-to, reference и explanation.
- [MADR](https://adr.github.io/madr/) — формат архитектурных решений.
- [Karpathy-Inspired Claude Code Guidelines](https://github.com/multica-ai/andrej-karpathy-skills/blob/main/CLAUDE.md) — сторонняя адаптация наблюдений Андрея Карпати: ясность, простота, точечные изменения и проверяемая цель. Это не файл, автором которого является Андрей Карпати.

## Обновление

Общие правила меняются в этом репозитории. Локальные особенности проекта остаются в его собственных `AGENTS.md`, `CLAUDE.md` и `.claude/settings*.json`; их не нужно переносить сюда. При изменении поведения обновляйте связанные документы и шаблоны, затем проверяйте ссылки, shell-синтаксис и конфигурацию по [инструкции](docs/setup.md#проверка).
