# Git и Merge/Pull Request

## Разрешения прежде команд

По умолчанию агент работает в текущей копии и на текущей ветке. Branch, worktree, commit, push, PR/MR, merge, release и deployment выполняются только при явном запросе и если клиентские правила их не запрещают.

Строгий профиль из `claude/CLAUDE.md` намеренно более ограничительный: он запрещает создание веток, worktrees, commit, push и PR даже при автоматических воркфлоу. Более локальное действующее правило важнее общего маршрута команды.

Не применять force-push, reset, rebase, удаление ветки или другие операции с историей без отдельного явного запроса.

## Самодостаточное изменение

- Один PR/MR — одно самостоятельное, отдельно вливаемое изменение, которое не ломает основную ветку.
- Исправление поведения и рефакторинг разделяются.
- Большая задача разбивается на цепочку независимых изменений, когда каждое можно проверить и влить отдельно.
- Общие правила применяются к затронутой области; полная миграция старого репозитория не добавляется к маленькому изменению.
- Нет жёсткого универсального лимита файлов: признак для декомпозиции — невозможность быстро понять и проверить изменение целиком.

## Коммиты

Если проект не задаёт другой формат:

- заголовок на английском, короткий, в повелительном наклонении и без точки;
- сообщение объясняет, что и зачем изменено; «как» видно из кода;
- ключ задачи добавляется по соглашению репозитория;
- каждый коммит осмыслен и желательно собирается;
- шумовые исправления объединяются только при разрешённой переработке собственной истории.

## Описание PR/MR

Описание пишется относительно целевой ветки, а не относительно последней итерации исправлений:

```markdown
## Что изменено

<коротко и по-человечески>

## Проверка

- <команда или сценарий и результат>

## Область для QA

<затронутое поведение и что проверить; если QA не требуется — по процессу команды>
```

После доработок описание обновляется как текущее состояние, а не превращается в историю раундов ревью.

## Готовность к вливанию

- Обязательные проверки зелёные.
- Все обязательные замечания разрешены с пояснением.
- Нужные апрувы и QA получены по процессу команды.
- Ветка актуальна; конфликты разрешены и после этого повторно проверены.
- Способ merge, squash и управление ветками соответствуют репозиторию.
- В релизной ветке потребителей нет случайных local/branch/snapshot-зависимостей.

Само вливание — отдельное внешнее действие и требует разрешения.
