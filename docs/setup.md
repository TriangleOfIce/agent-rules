# Установка на новом устройстве

## Требования

- Git и доступ к репозиторию по SSH или HTTPS.
- macOS/Linux с Bash для `bootstrap.sh` и hooks.
- Для Claude hooks — `jq` в `PATH`.
- Для проверки Kimi Code — установленная команда `kimi`.

## 1. Подключить общие правила к рабочему каталогу

```bash
git clone git@github.com:TriangleOfIce/agents.git
./agents/bootstrap.sh /path/to/Work
```

`Work` — каталог, внутри которого находятся рабочие репозитории. Скрипт создаёт:

```text
Work/
  AGENTS.md -> <clone>/AGENTS.md
  CLAUDE.md -> <clone>/CLAUDE.md
  agent-conventions -> <clone>
  memory/projects.md
  process/
  backlog/README.md
```

Символические ссылки позволяют получать обновления через `git pull` в клоне. Существующие файлы не перезаписываются. При конфликте объедините правила вручную: локальные инструкции проекта должны остаться на своих местах.

Заполните `memory/projects.md` фактами о проектах нового устройства. Этот файл локальный и не должен попадать в репозиторий общих правил.

## 2. Настроить Kimi Code

Актуальная схема конфигурации: [официальная документация](https://moonshotai.github.io/kimi-code/en/configuration/config-files.html).

1. Запустите Kimi Code и выполните `/login`, чтобы managed provider создал актуальные модели и OAuth-настройки.
2. Определите каталог данных: непустой `KIMI_CODE_HOME`, иначе `~/.kimi-code`.
3. Сохраните текущий `config.toml`. Не заменяйте его примером целиком.
4. Перенесите из `kimi-code/secondary-model.snippet.toml` секции `[thinking]`, overrides двух моделей и `[secondary_model]` в копию `config-new.toml`. Если секции уже существуют, объедините их, не дублируйте заголовки TOML.
5. Основную модель выберите отдельно. Пул субагентов не требует смены основной модели. Для повторения исходного выбора укажите в начале `config.toml` `default_model = "kimi-code/k3.1-pro"`, если эта модель доступна после `/login`; глобальный `[thinking].effort` в примере уже равен `high`.
6. Проверьте кандидат:

```bash
kimi doctor config /path/to/config-new.toml
```

7. Только после успешной проверки создайте новую timestamped backup-копию и замените активный файл:

```bash
cp config.toml "config.toml.$(date +%Y%m%d-%H%M%S).bak"
mv config-new.toml config.toml
kimi doctor
```

8. В текущей сессии выполните `/reload`; новая сессия подхватит файл автоматически.

Важно: `[secondary_model].default_effort` специально отсутствует. Этот параметр действует на весь пул и переопределил бы high effort у K3. Effort задан отдельно в overrides каждой модели. Псевдонимы пула должны существовать в `[models]`; после смены provider или logout проверьте их повторно.

`tui.toml` содержит только общие UI-предпочтения. Его можно использовать как reference, но при переносе также сначала проверяйте кандидат: `kimi doctor tui /path/to/tui-new.toml`.

Не копируйте между устройствами `credentials/`, `oauth/`, `server.token`, `device_id`, сессии, историю, backups и ключи из активного `config.toml`. Авторизация выполняется заново на каждом устройстве.

## 3. Архивный профиль Claude Code — не обновляется

Мы больше не работаем с Claude Code. Каталог `claude/` сохранён только как архивный снимок для справки; его настройки и hooks не поддерживаются и не обновляются. Новые устройства не нужно настраивать по этому разделу.

Базовый `CLAUDE.md` в рабочем каталоге уже подключает общие `AGENTS.md`. Отдельный каталог `claude/` нужен только для воспроизведения более строгих личных правил:

- запрет создания веток и worktrees;
- запрет commit, push, создания и merge PR;
- запрет публикации без явного запроса;
- дополнительные правила решений, диагностики, коммуникации и Kotlin.

Эти запреты сильнее общего `AGENTS.md` и могут блокировать действие даже при автоматическом воркфлоу. Включайте их осознанно.

1. Объедините `claude/CLAUDE.md` с `~/.claude/CLAUDE.md`, сохранив существующие локальные правила.
2. Скопируйте hooks из `claude/hooks/` в `~/.claude/hooks/` и сделайте их исполняемыми.
3. Объедините `claude/settings.example.json` с `~/.claude/settings.json`. Это не файл для слепой перезаписи: plugins, модель и UI можно оставить своими, но matcher и пути hooks должны совпадать.
4. Kotlin-правило при необходимости скопируйте в `~/.claude/rules/kotlin.md`.
5. Проверьте `jq` и `bash -n ~/.claude/hooks/*.sh`, затем начните новую сессию.

В шаблон намеренно не включены status line, machine-specific auto mode, локальные пути и исключения доверенных каталогов.

## 4. Настроить локальные проекты

Для каждого проекта сохраните его собственные инструкции. Если их нужно создать, начните с `templates/project.AGENTS.md` и укажите только подтверждённые особенности:

- стандартные команды build/test/lint;
- обязательную генерацию;
- запрещённые пути;
- локальные правила безопасности;
- специфичный процесс публикации.

Общие принципы не дублируйте в проектном файле без необходимости.

## Проверка

После установки:

- `AGENTS.md`, `CLAUDE.md` и `agent-conventions` доступны из рабочего каталога;
- все относительные ссылки в Markdown разрешаются;
- `bash -n bootstrap.sh claude/hooks/*.sh` проходит;
- `bootstrap.sh` успешно создаёт структуру в пустом временном каталоге и не перезаписывает существующие файлы;
- `kimi doctor` проходит после объединения конфигурации;
- в новой сессии доступны две secondary-модели с low/high effort;
- hooks Claude отклоняют запрещённые тестовые команды и пропускают read-only Git;
- поиск по репозиторию не находит токенов, OAuth-ключей, локальных карт проектов и абсолютных домашних путей.

## Обновление

Обновляйте клон отдельной явно запрошенной операцией. После обновления повторите проверку ссылок и установки в пустом каталоге. Изменения активного `config.toml` Kimi и глобального `settings.json` Claude не выполняются автоматически.
